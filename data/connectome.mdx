The FlyWire connectome underpins every simulation in Fly Brain. It provides the full neuron list and synaptic connectivity graph that is loaded by each backend at startup — Brian2, Brian2CUDA, PyTorch, NEST GPU, GeNN, and Brian2GeNN all read from the same source files so results are directly comparable.

## Data Files

| File | Description | Size |
|---|---|---|
| `data/2025_Completeness_783.csv` | Neuron IDs and metadata (FlyWire v783) | 3.2 MB |
| `data/2025_Connectivity_783.parquet` | Pre/post-synaptic indices + weights | 97 MB |
| `data/weight_coo.pkl` | Sparse COO weight matrix (auto-generated by PyTorch) | ~288 MB |
| `data/weight_csr.pkl` | Sparse CSR weight matrix (auto-generated by PyTorch) | ~289 MB |
| `data/archive/2023_Completeness_630.csv` | Legacy v630 neuron list | — |
| `data/archive/2023_Connectivity_630.parquet` | Legacy v630 connectivity | — |

## Connectivity Parquet Schema

The connectivity file `2025_Connectivity_783.parquet` exposes three columns consumed by every backend runner:

- **`Presynaptic_Index`** — integer neuron index of the pre-synaptic neuron within the completeness DataFrame
- **`Postsynaptic_Index`** — integer neuron index of the post-synaptic neuron within the completeness DataFrame
- **`Excitatory x Connectivity`** — synaptic weight value; positive for excitatory connections, negative for inhibitory connections (already sign-flipped by the upstream data pipeline)

At load time the PyTorch backend constructs a sparse tensor of shape `(138k, 138k)` from these three columns and scales the values by `wScale = 0.275` before simulation begins.

## Completeness CSV

`2025_Completeness_783.csv` contains one row per neuron. The **DataFrame index** is the FlyWire neuron ID (a 64-bit integer), not a contiguous zero-based integer. The file is used by the PyTorch backend's `get_hash_tables()` function to build two lookup dictionaries:

- `flyid2i` — maps each FlyWire ID to its contiguous integer row index (used to locate neurons in the weight matrix)
- `i2flyid` — the inverse mapping, used when annotating spike output with FlyWire IDs

All backends use the neuron ordering established by this CSV, so neuron index 0 in a spike parquet always refers to the same cell across frameworks.

## Data Versions

- **v783 (2025)** — current version used by all benchmark runners and the canonical `nature_2026_07` publication dataset. Both `2025_Completeness_783.csv` and `2025_Connectivity_783.parquet` are tracked in Git.
- **v630 (2023)** — archived version kept in `data/archive/` for reproducing original paper figures from `code/paper-brian2/figures.ipynb`. Not used by any benchmark runner.

## Weight Cache Files

`weight_coo.pkl` and `weight_csr.pkl` are generated automatically by the PyTorch backend (`get_weights()`) on its first run and cached to `data/` for reuse on all subsequent runs. Building them from scratch takes a noticeable amount of time, so caching is important for iterative benchmarking. Both files are listed in `.gitignore` and must not be committed to the repository.

- `weight_coo.pkl` — PyTorch sparse COO tensor, ~288 MB
- `weight_csr.pkl` — PyTorch sparse CSR tensor (converted from COO), ~289 MB

The CSR format is the default for simulation because sparse CSR matrix–vector products are more cache-friendly on GPU than COO during the recurrent `torch.matmul` step in each simulation timestep.

## Loading the Data

The following snippet shows how the PyTorch backend loads the weight matrix and builds the neuron ID hash tables. It mirrors the internal calls in `code/run_pytorch.py`:

```python
from run_pytorch import get_weights, get_hash_tables

flyid2i, i2flyid = get_hash_tables('data/2025_Completeness_783.csv')
weights = get_weights(
    'data/2025_Connectivity_783.parquet',
    'data/2025_Completeness_783.csv',
    'data/',
    csr=True
)
# weights is a sparse CSR tensor on GPU, shape (138k, 138k)
```

Pass `csr=False` to retrieve the COO tensor instead. The function transparently reads from the pickle cache when available and builds the matrix from the Parquet file otherwise.

<Note>
`weight_coo.pkl` and `weight_csr.pkl` are gitignored and will be generated automatically the first time the PyTorch backend runs. Expect a one-time delay of several minutes while the sparse matrix is constructed and serialized.
</Note>
